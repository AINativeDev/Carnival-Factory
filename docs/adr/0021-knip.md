# 0021. Knip finds unused code, exports and dependencies

- Status: Accepted
- Date: 2026-11-25
- Spec: [checks-and-tests.md](../specs/checks-and-tests.md)

## Context

The repository changes fast and mostly by agents, which add code readily and
remove it rarely. Unused files, exports and dependencies make files bigger,
mislead the next reader and widen what a dependency update can break.

## Decision

Knip runs in `npm run check`: an unused file, export or dependency fails it.
Its entry points are the pages, the square files the map finds by glob, the
scripts the workflows run, and the tests.

## Alternatives considered

- **Review catches dead code.** Rejected: reviews look at what changed, not at
  what a change left behind.
- **TypeScript's unused checks only.** Rejected: they see unused locals, not
  unused files, exports or packages.

## Consequences

Removing a use of something means removing it too, in the same change. Code
reached in ways Knip can't see must be declared as an entry, not ignored.
